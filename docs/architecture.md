# AppHub 当前架构

更新：2026-11-03。执行规则见 [AGENTS.md](../AGENTS.md)，实际验收见 [status.md](status.md)。本文只描述当前决定，未来能力不作为已实现接口。

## 服务边界

```text
DSH 普通聊天 / AppHub 页面
          ↓
DSH 适配层（Remote、工具身份、会话调用）
          ↓
AppHubApplication（校验、任务分发、去重）
          ↓
备忘录业务服务 → 备忘录仓储
```

UI 只接收状态和回调；客户端适配层连接控制器与官方服务。application 定义业务和仓储接口，不反向依赖 adapter。contracts 仅放 JSON 契约。当前 UI 可直接复用公开、无 Cordis 依赖的 ui-primitives；这不是允许 UI 使用宿主服务的例外。

AppHubApplication 内的 node:crypto 仅用于 ID 和参数摘要；OS 路径、文件、SQLite 与启动释放仍归 adapter。纸色顺序与默认分配集中在 application/notes.ts；展示组件不能从另一个页面导入业务元数据。

## 数据与调用

```text
DSH_HOME/apphub/
├── hub.sqlite               # 登记、公共设置、任务
├── apps/notes/data.sqlite   # 便签、应用设置
└── notes.sqlite             # 迁移前旧库，保留且停止写入
```

旧 schema 1/2/3 经事务复制到分库，逐字段校验便签、设置与任务后记录迁移成功。失败回滚，可以修复原因后重试。不双写，不直接回退到使用旧库的代码。没有文件业务需求，不创建 files/。

工具参数仅 title/body。Host 从 exec.agent.id、exec.callId 取得可信调用上下文并授予 notes.create；不接受模型自报授权或任意路径。prepareTask 只关联 AppHub 发起的任务，不作为普通会话授权条件。

任务先持久化稳定 noteId 与参数摘要，再保存便签。同一会话与调用编号重试返回原结果；相同键换参数拒绝。保存完成但任务回执丢失时，实际便签用于恢复结果。窗口编辑使用 revision 拒绝旧版本覆盖。

Hub 数据仅由 Hub 仓储维护，备忘录数据仅由应用仓储维护；启动迁移是一次性的跨库边界例外。应用初始化失败不阻塞首页和 Hub 设置，业务请求返回不可用。

## 进程决定

当前业务运行在 DSH Host 内。已核查官方 ctx.subprocess，它管理进程启动、终止、退出等待和释放清理，但把应用协议、就绪检查与超时交给消费者。桌面 DesktopHostProcess 是私有引导实现，不是插件应用托管接口。

因此当前不建立 IPC/监管框架、不复制私有代码、不改宿主。将来确需独立服务时复用 ctx.subprocess 的进程生命周期，再补必要通信。现在只有逻辑隔离，不承诺恶意代码、Host 崩溃、阻塞或内存耗尽隔离。多窗口共用数据与版本校验已有基础，但变更推送和自动刷新未实现。

## UI 与主题

- 官方控件：Button、Input、SegmentedTabs、Menu/MenuItemButton、Modal、Toast、Tooltip、通用图标，由宿主预加载模块表提供。开发依赖固定 0.2.1-rc.5，构建 external，不复制控件实现或打包第二份 React。
- 官方没有通用整页组件；参考 PluginManagerPage 的结构；当前内容宽度收敛为 900px，20px/28px 标题、28px 顶部间距和 frame clearance。业务卡片保留断点布局，编辑器共用一份。
- 公共文本使用宿主字体；便签正文使用 --dsh-content-font-size。颜色、圆角、焦点和交互态使用 --dsw-*。
- ui/appearance.css 集中独立外观适配。只有选择与宿主相反的浅暗色时才覆写局部别名；跟随及相同模式直接继承宿主皮肤。portal 弹窗显式携带本应用外观类，不能改全局主题。
- 纸色圆点和设置中的主题预览可以有固定展示色；不能用其代替通用主题。原生正文/标题输入及任务多行输入是业务编辑面，不重写通用按钮、弹窗等行为。
- 第三方使用公开 tokens 与 primitives 的皮肤可沿这些接口继承；没有安装第三方皮肤实测，不能保证修改私有 DOM 的皮肤兼容。

## 已撤回与保留限制

已撤回：独立测试实例/新 profile、连接检查与成功时间、备忘录聊天侧栏/卡片栈、首页返回聊天、手动保存和重复设置菜单。不得依据旧研究重新引入。

保留：AppHub 与应用设置分别持久化；空白新便签关闭时丢弃未落库草稿；已有内容自动保存失败保留草稿并提供重试；连接请求有 15 秒超时并显示未确认，不自动重提；会话运行超过三分钟仍继续跟踪。刷新后任务进度订阅恢复尚未实现。手机端依赖 DSH 在线，只是后续方向。

## 防回退

check:boundaries 在构建前检查常见依赖和样式越界。它不是安全沙箱，也不替代官方接口核查、代码审查及桌面行为验收。规则变更写回本节及 AGENTS.md，不新增隐式白名单。

## P09：应用工作区与悬浮任务框

用户已授权尝试 AppHub 内部左右分栏。左侧目录/应用导航，右侧应用，底部共享 TaskComposer；窄屏导航改顶部。不是宿主侧栏扩展。任务草稿由客户端 Surface 持有，切页不清空。当前仅备忘录一个可执行应用，任务框明确显示目标，默认新建；显式 @ 继续通过既有能力校验。提交时解析任务并交给原 runner，后续导航不改变已提交任务。没有增加更新便签、会话长期绑定或新进程。内容区预留任务框高度，编辑弹窗使用宿主 Modal 覆盖工作区。

任务不独占应用：每次提交拥有独立会话引用和轮询，发送请求完成后即可再次提交。一次会话可多次调用 notes.create；按同一会话的保存操作汇总成功、失败和待确认数量，必须等待会话结束；存在失败或待确认时保留异常结果，不按首张成功认定全部保存。此汇总针对实际工具调用，不推断自然语言要求的预期张数。完成只刷新列表，不选择便签或打开编辑器；编辑未保存时延迟刷新，避免干扰草稿。失败单独保留会话入口，不取消其他任务。刷新窗口后恢复运行中任务仍未实现。

任务反馈使用公开组件：输入框目标行放聚合数量，Menu 展开各会话，异常使用官方 Toast；禁止恢复顶部逐条常驻横幅，成功不自动弹窗。

## P10：收尾与恢复

通用操作图标、悬停提示、任务菜单、通知均复用官方 ui-primitives；保留 AppHub/备忘录品牌图标及业务编辑面。任务菜单向上展开，失败记录可移除；移除只清前端异常记录，不删除会话、便签或取消运行任务。正式便签和应用设置仍只存 apps/notes/data.sqlite。

未确认保存的编辑增加恢复日志：application 仅依赖同步 DraftJournal 接口；client 适配层使用当前桌面 origin 的 localStorage 专用前缀 dsh-apphub:notes:unsaved:v1:。这是仅供退出/热重载恢复的临时副本，不是正式数据库、跨设备同步或第三方插件沙箱。每次编辑同步记入，收到保存回执后清理；回执丢失但数据库内容一致时消除重复恢复项。与数据库版本冲突的恢复明确创建副本，不覆盖新版本。恢复入口位于列表，不自动弹出编辑器。存储失败明确提示保护失败，不声称可恢复。多窗口同时编辑同一便签的恢复日志协调尚未实现。

切到后台及 beforeunload 尝试提前保存；不依赖退出阶段异步调用保证落库。强制终止、系统掉电或宿主清除站点存储仍不能承诺零丢失。应用控制器卸载/重建、确认丢失和冲突恢复用合成存储测试；未故意强杀用户桌面。

列表加载错误独立于编辑保存状态，保留既有列表并提供重试；不因失败将已保存内容伪装成空列表。

## 新应用接入约定

这是第二应用实现时应遵循的接入清单，**不是已经实现的通用插件 API**。备忘录作为回归样本，保留现有保存逻辑。

| 项目 | 最小约定 |
|---|---|
| 应用登记 | 一个稳定 appId、名称、图标、实际页面和能力列表；先用静态定义表，目录、导航、@ 候选共用；无占位应用 |
| 能力声明 | appId + 明确 operation + 参数/结果契约；例如现有 notes.create。只声明能执行的操作，打开页面是 UI 导航，不冒充业务操作 |
| 任务目标 | 输入框跟随所选应用；提交时固化目标，后续切页不改变已提交任务；会话生命周期共用，业务提示和结果刷新由对应应用提供 |
| 调用身份 | Host 提供会话与调用编号，模型不能声明身份/授权。不同应用的允许操作显式列出，不把提示词当权限控制 |
| 数据归属 | apps/<appId>/data.sqlite 保存该应用业务和设置；hub.sqlite 只存公共设置与任务/关联。不能让新应用读写 notes 库 |
| 结果关联 | 一个任务允许多个结果；引用必须包含所属应用与结果类型/ID。迁移旧 noteId 时保留 notes 归属和原幂等记录，不破坏已保存便签 |
| 页面与设置 | UI 收状态/回调，地图 SDK 等外部 I/O 归适配层；通用控件/tokens 复用 DSH。Hub 设置与应用设置分开，不复制整套页面/保存控制器 |
| 外部能力 | 网络请求、密钥、限流与提供商错误由 Host 适配器处理；密钥不得进入模型参数、结果、客户端包或日志。外部结果与本地保存分别确认 |
| 失败与释放 | 每应用加载失败不能拖垮首页；超时不是保存成功；监听、请求、SDK 实例随页面/插件释放；不要为第二应用引入进程框架 |

接入验收只要求实际链路：同一入口从普通聊天和 AppHub 访问同一业务服务；notes 与第二应用可交替/并行运行且结果不串应用；错误不影响其他应用；重开读取一致；UI 及业务复用不靠宿主私有接口。真实模型和外部计费调用须在明确的验收范围内进行。

当前源码仍有 notes 硬编码，清单见 status.md。第二应用需要时才抽取共用部分，不为第三、第四应用预先设计加载器、权限面板或工作流 DSL。
