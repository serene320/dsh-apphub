## 保留限制

- 窗口刷新/重启后尚不能恢复运行中任务的前端进度订阅；数据不因此自动丢失，不能自动重发任务。
- 完整多窗口通知同步未实现；同步草稿日志也未处理多窗口同时编辑同一便签。普通目录不是安全沙箱。
- 保存汇总针对实际进入服务的调用，不能推断模型是否满足自然语言中要求的全部张数或内容。
- 强制退出/掉电、存储配额、卸载、异常重连、拼音组合输入和第三方皮肤还需针对性实机验收。
- 同 Host 进程只提供逻辑隔离，不保证崩溃、阻塞、内存耗尽或恶意代码隔离。

## 松键与卡片点击修复（2026-11-03）

用户反馈松开 Command 后选择未退出。发现此前 keyup 只在页面 React 子树冒泡监听，macOS 鼠标点击未让按钮取得焦点时可能漏接；改为 client 适配层窗口 capture 监听，页面退出注销，失焦/隐藏/Escape 取消。释放时先清空选择再打开链接，避免外部浏览器抢焦点干扰清理。

卡片主按钮命中区域扩展到整个条目，覆盖标签和底部留白；编辑/选择按钮保持独立上层。原桌面实测底部留白点击新增了正确的 Chrome 标签，标签区域 Command 点选及 Escape 退出正常，编辑按钮仍打开编辑框。55 项测试和构建通过，新增窗口事件与注销测试；自动化仍不能发送独立物理 Command 松键，不能把合成事件测试称为完整物理手势验收。

空选择补充修复：松键处理先检查是否处于空选择，不再仅依赖修饰键点选标记；手动进入但未选择、选中后再次取消到零条均返回普通状态且不打开网页。选择勾选框也记录 Command/Control 标记。56 项测试与构建通过；物理松键仍待用户现场验证。

## 间歇手势恢复（2026-11-03）

用户继续反馈偶发无效。修复两项代码风险：选择状态改为同步的小型状态对象，事件处理不等 React 重渲染读取最新选中项；适配层记录实际修饰键状态，若 keyup 丢失，后续 pointermove 确认 Meta/Control 均释放时只完成一次。没有计时器猜测松键；窗口失焦/隐藏取消，不延迟打开。普通手动多选不会因无修饰键鼠标移动退出。

57 项测试与构建通过。新测试串联实际事件监听和同步选择模型，覆盖无重渲染快速点选/释放、丢失 keyup、重复事件、全取消到空、双修饰键与失焦取消。当前 DSH 桌面模拟 Command 点选后缺少独立释放事件，通过空白区域指针移动触发恢复，AX 多选回到 0，Chrome 目标 URL 标签数从 0 到 1。该结果验证丢事件恢复路径，不代表全部物理键盘时序已长期验收。
